# S218BP exact Level 3 first-pass benchmark — 2026-09-01

## Test system

- NVIDIA GeForce RTX 2080 Ti, 11,264 MiB VRAM
- 16 logical CPU threads
- S218BP example, expanded from XY symmetry to the arbitrary-incident-field full domain
- 100 Hz, two independent full-domain driver excitations
- BEAT CUDA, FP32, quadrature order 2

[`examples/S218BP/level3-benchmark-request.json`](../../examples/S218BP/level3-benchmark-request.json).

## Timing

The first successful full-domain run recorded 65.28 s from solve start to solve
finish, including cold Julia/CUDA setup and frequency-invariant mesh/operator
preparation. The frequency completed in under one minute once the worker had
accepted the request. Full-domain Python mesh expansion initially took several
minutes because the point array was rebuilt for every surface facet; building
it once reduced that stage to seconds.

## Deploy implementation and measured runtime

Deploy now stages one transformed copy of the exact compiled physical system
per cabinet, assembles the cabinets and rigid objects into one shared exterior,
and submits every electrical port as a right-hand side of one coupled
factorization. Gain, delay, and polarity are applied before one synthesized
audience-field evaluation. Rigid ground uses the BEM ground image without
duplicating the FEM volume or physical transducer.

Measurements use a persistent Julia worker, a 17 x 17 audience plane, FP32,
quadrature order 2, and 100 Hz. `warmup` below means the first request in a new
worker; `measured` means the immediately following request in that worker.

| ---: | --- | ---: | ---: | ---: | --- |
| 1 | warmup | 43.409 s | 1.574 s | 41.835 s | completed |

| 2 | warmup | 83.949 s | 3.023 s | 80.926 s | completed |

The anomalous two-cabinet second request is real: its FEM condensation
factorization took 101.494 s while the first request reported 0.105 s for that
stage. Explicit worker-end CUDA reclamation prevents prior solve objects from
remaining resident, but the full-order two-cabinet solve still operates at the
2080 Ti memory ceiling and is not a viable interactive configuration.

The benchmark is reproducible with `scripts/benchmark_deploy_level3.py`.
Generated staging data remains under ignored
`runs/.deploy_level3_benchmark/`.

## Runtime architecture and gate

The full-order implementation passes the one-cabinet warm gate but decisively
misses it for the intended 4–8 cabinet workflow. Sharing only the interior
factorization will not be enough: four full-domain S218BP exterior boundaries
produce a solved order of roughly 32,648, so the exterior dense matrix and its
factorization also exceed the 2080 Ti working set. The next implementation must
reduce both the package boundary representation and interior response.

Proceed in this order:

1. Four parity-sector solves for XY-symmetric cabinets, with arbitrary incident
   data decomposed and recombined across the sectors.
2. A validated interface/port-reduced affine model on a reduced exterior
   boundary basis, increasing rank until its
   pressure, input-impedance, diaphragm-velocity, and mutual-loading errors meet
   the package acceptance tolerances.

Do not make the current combined full-order path the default for large arrays.
It is useful as the one-cabinet reference implementation and as an oracle for
validating reduced models.
